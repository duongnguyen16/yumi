# WDP-31 and WDP-32 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver canonical RequestAccess appeal and ownership dispute flows from NestJS backend through Admin Web and Vendor Mobile without changing unrelated task behavior.

**Architecture:** Appeals validate and snapshot an existing adverse decision, then either uphold it, restore it through a focused dispatcher, or escalate a rejected RequestAccess into one Dispute. Disputes expose participant evidence endpoints and Admin resolution endpoints. Existing AuditService, NotificationPort, schemas, AdminGuard, Admin UI primitives, and Mobile service conventions are reused.

**Tech Stack:** NestJS 11, Mongoose 9, Jest 30, Next.js 16 App Router, React 19, MUI 9, Expo Router 56, React Native Paper, TypeScript.

## Global Constraints

- Scope is limited to WDP-31 and WDP-32 behavior.
- `docs/CONTEXT.md` overrides stale guideline text.
- RequestAccess rejection plus accepted requester appeal is the only source of a new Dispute.
- Admin-decided ownership transfer never enables hold.
- Pending appeals keep the adverse target state unchanged.
- Code uses short entry-level names and adds no comments.
- Do not create commits or push changes.
